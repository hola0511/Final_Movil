## 2. Objetivo

autenticación, roles, eventos, inscripciones, asistencia,
sincronización offline, HTTP/JSON, SharedPreferences y
Crashlytics.

permisos definidos en Firebase Firestore.

## 6. Criterios de aceptación

- La aplicación compila sin errores.
- Se respetan los permisos de los tres roles.
- No se sobrepasa la capacidad de los eventos.
- No se admiten inscripciones duplicadas.
- No se permite reducir aforo bajo confirmados.
- No se permite registrar dos veces un ingreso.
- Las solicitudes offline sobreviven al reinicio.
- Los conflictos se conservan con motivo.
- El catálogo HTTP responde correctamente.
- SharedPreferences conserva la preferencia.
- Crashlytics recibe el error de prueba.
- Los errores detectados se documentan y corrigen.
